# Укрепление прототипа после первого smoke

Работа начата 22 октября 2026 в 22:30 MSK по запросу продолжить улучшение ещё час. Старые execution bundles и assessments сохранены. Это инженерная итерация на development corpus; ручного reference и независимой оценки factual accuracy по-прежнему нет.

## Что изменено

- В `blinded-context-0.2` явно передаются дата создания комментария и статус истории его текста. Отсутствующее значение не заменяется сегодняшней датой. Для `current_only` нельзя утверждать, что на t0 был именно такой текст.
- Начальный контекст и инструменты показывают строки в виде `123 | code`. Декорация существует только в представлении для модели. Canonical excerpt, chunk ID и материализуемая цитата сохраняют исходный текст. Лимит tool output учитывает размер отображения.
- При неверном пути `read_lines` возвращает существующие варианты с тем же именем файла; при неверном диапазоне сообщает длину файла. `search_text` отличает отсутствие подходящих путей от отсутствия совпадений. Подсказка о файле не регистрирует его содержимое как показанное evidence.
- Prompt явно требует supports evidence и для partially_supported, а publish допускает только при всех factual claims supported. Правила validator не ослаблены; judgments не исправляются компилятором.
- Offline `compare` сопоставляет только общие samples с совпадающими hashes, отдельно считает pending, восстановленные случаи и регрессии. Совпадение deployment metadata не выдаётся за fingerprint весов.

## План измерения, зафиксированный до новых ответов

Первый run `hardening-v02-63c3729bc8d9`: 16 agent assessments. Взяты все 8 прежних evidence failures, 4 semantic failures и 4 successes из `smoke-compact-e998172b268c`. В последних двух группах применён прежний детерминированный repo round-robin. Selection manifest находится в `data/manifests/hardening-selection.json` и копируется в завершённый run. До изменения на этих 16 samples все validators проходили у 4.

Отдельно повторяются два ранее исследованных Sourcery-комментария с человеческими дизлайками из Nuitka. Их reactions остаются закрыты для модели. Эти примеры целенаправленно выбраны для отладки, поэтому доли нельзя переносить на весь GitHub или рабочий поток.

## Вариант ссылок на целые фрагменты

В первом новом прогоне уже обнаружен случай, где модель выбрала диапазон 296–304 для chunk, начинающегося со строки 300. Нумерация не устранила такую ошибку привязки. Поэтому подготовлен отдельный контракт `compact-0.3.0`: модель ссылается на целый показанный chunk и не выдаёт subrange. Для более узкой цитаты она может сначала запросить меньший диапазон через `read_lines`.

Это уменьшает число способов ошибиться в ссылке, но делает некоторые цитаты длиннее. Неизвестный chunk по-прежнему отклоняется, а relation=context по-прежнему не подтверждает supported. Формат с subranges сохранён как `compact-0.2.1`; исходные outputs не переписываются. Рост evidence validity при упрощении контракта сам по себе не означает рост factual accuracy.

Первая итерация завершена. На одинаковых 16 samples:

| --- | --- | --- | --- |
| Все validators passed | 4/16 | 12/16 | 15/16 |
| Evidence valid | 8/16 | 12/16 | 15/16 |
| Raw schema valid после допустимого repair | 16/16 | 15/16 | 15/16 |
| Суммарное время завершённых attempts | 1097.066 s | 1312.967 s | 1233.551 s |
| Tool calls | 133 | 139 | 136 |

Восстановлено 9 прежних failures, один прежний success стал evidence_invalid. Остались 3 evidence_invalid и 1 json_invalid. В последнем случае обе финальные генерации завершились stop_reason=length; точная причина обрыва в старом trace не установлена. Разные изменения внесены вместе, поэтому приписать эффект только нумерации нельзя. Сопоставление сохранено в `runs/hardening-v02-63c3729bc8d9/comparison-agent.json`.

`reaction-v02-96f6a5f9b4fe`: оба agent assessments проходят validators, без format repair. В примере `function.__builtins__` агент прочитал `tests/basics/run_all.py` и корректно описал функцию как возвращающую dict; прежняя путаница с глобальным именем в этом ответе отсутствует. Окончательный вывод об устойчивости теста остался неопределённым, реакция пользователя — negative без изменения. Это диагностика конкретного примера, не независимая human annotation. Для checkout агент использовал дату 2026-03-15 и оставил факт внешней доступности версии неизвестным.

Контракт с целыми chunks завершил отдельный run `whole-chunk-v03-44e09f611f1c` на тех же 16 samples: **15 ok / 1 json_invalid**. Все 15 принятых outputs проходят также source и cross-field validation; ошибок диапазонов нет. По сравнению с исходным smoke восстановлено 11 failures, регрессий среди четырёх прежних successes нет. По сравнению с промежуточным numbered/subrange run восстановлено 4 failures, но один его success стал json_invalid. Поэтому утверждать отсутствие регрессий между всеми версиями нельзя.

Суммарное время — 1233.551 s, tools — 136: исходные 1097.066 s / 133 tools и промежуточные 1312.967 s / 139 tools относятся к тем же 16 samples. Основной response contract в default config теперь `compact-0.3.0`; клиентский context budget пока сохраняет 32768, как в этом измерении. `compact-0.2.1` остаётся доступным. Это выбор формата для инженерного прототипа, не подтверждение пригодности teacher для автоматического обучения.

В основном 0.3.0 run было три format repairs. Две пары ответов разбираются до и после; в сравниваемых полях изменений не обнаружено. Третья попытка repair не дала разбираемого ответа. Это проверка ограниченного набора полей, не доказательство смысловой эквивалентности.

Оставшийся failure — `gh-6b04087fd6936168e90e7341`: в исходном JSON отсутствовали evidence_links у двух factual claims, а format repair вернул пустой visible ответ с stop, не length. В repair запрос ушёл с max_tokens=5405 вместо 8192. Причина ограничения подтверждена исходниками установленного Pi 1.3.0 (`pi-ai/dist/api/simple-options.js`): maxTokens ограничивается `contextWindow - estimateContextTokens - 4096`, снизу до 1. Это объясняет снижение отправленного лимита, но не доказывает причину пустого ответа модели.

`reaction-whole-v03-e677b7509a44` завершён: оба agent assessments проходят validators. В примере builtins модель корректно описывает getter как возвращающий dict и учитывает сравнение с CPython, оставляя внешние детали явно неизвестными. Обе исходные negative reactions сохранены; ни одного исправленного пользовательского label не создано.

Профиль client context=65536 отдельно проверен при подтверждённом серверном metadata n_ctx=131072. Run `context64k-probe-0b2d90e87e44`: **2/2 ok, 0 repairs**, один прежний json_invalid восстановлен и один success сохранён. Во всех 13 фактически отправленных запросах max_tokens=8192; суммарное время — 159.100 s. Это два целенаправленно выбранных случая, а не повтор всех 16 и не доказательство причинного эффекта на factual quality. Профиль сохранён в игнорируемом `configs/context64k.local.json`; default остаётся 32768, как в измерении 15/16. Для другой модели ёмкость контекста нужно проверить заново.

## Проверки и эксплуатация

69 Python tests прошли после подключения обоих response contracts, восстановления interrupted queue, проверки неопределённых reaction actors и ZIP verifier. Среди них 18 реальных Pi SDK loopback scenarios: два контракта × девять исходов. TypeScript tools имеют 8 tests. Посторонние AGENTS/files не доступны через инструменты; тестовый ключ удаляется из сохранённых ошибок.

Новый `request_payload` trace содержит фактически отправленный max_tokens, размер messages, число messages/tools и флаг завершения tool phase. Prompt, headers и секреты этим событием не записываются. Для interrupted queue восстановление уже сохранённого result.json не запускает модель; отсутствие результата создаёт новую attempt, сохраняя предыдущие файлы. Неизвестный actor/thumb даёт incomplete signal даже при полной пагинации, а не однозначный positive/negative.

Source ZIP создаётся с новой версией имени и не перезаписывает прежний. `scripts/verify_package.py` проверяет inventory, SHA-256 каждого файла, отсутствие data/runs/dependencies и очищенный model config; это проверка упаковки, не универсальный поиск всех возможных секретов.

Все пять новых frozen bundles прошли resume dry-run с проверкой source/data hashes, без model requests. В 525 проверенных файлах этих runs, включая runtime-файлы, не обнаружено значения используемого credential; это проверка конкретного известного ключа, не поиск любых секретов. Прежний ZIP v0.1.0 сохранил исходный SHA-256 `0b8fa88d675531b333b753f4183af93f79a15c00ff208f74a30f20905c523c6d`.

За итерацию выполнены 38 дополнительных model assessments: 16+2 с subranges, 16+2 с целыми chunks и 2 с отдельным профилем контекста. Исходный полный corpus 40×3 повторно не запускался. Новые LoRA не обучались; человеческая разметка и шум пользовательских реакций не измерены. Пакет исходников этой итерации — `dist/aicr-prototype-0.2.0.zip`.
